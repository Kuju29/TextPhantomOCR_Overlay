Off by default. Shown because this URL is on your machine or your own network. The API's admission gates exist to share one server between several people; a local API has one. Turning this on lets Lens uploads and AI calls skip those gates.
Two things stay paced on purpose: Google Lens is still a remote service, so the extension keeps spacing uploads to it, and ONNX grouping is bound by your real CPU cores, where more parallelism is slower, not faster.
Extension decodes Lens, builds the layout, samples colours and draws the overlay in your browser. The API only does three things: the Lens upload, ONNX bubble grouping, and the AI translation call.
API server is the older split: the server runs Lens, ONNX, the AI call, the erase, the fonts and the HTML, and sends back a finished overlay or image. Slower per page and it uploads the whole picture, but it needs almost nothing from the browser — useful when a site fights the overlay, when a page is too large for the local renderer, or to compare the two.
Both engines use the same AI contract, the same Lens client and the same per-key pacing, so switching does not change the translation you get.
